# Learning Notes · 我的学习经历笔记

[English](README.md) | [简体中文](README.zh-CN.md)

一个帮助你回忆**“我是怎样学会的”**的 Codex skill。

它根据真实对话、练习、截图和操作记录整理笔记，保留笔记主人当时的疑问、误解、修正和仍未理解的地方。知识点沿着学习过程串起来，让笔记有熟悉感，也便于以后快速找回要点。

## 用一条主线串起来

```text
我原本想解决什么？
        ↓
我卡在哪里？
        ↓
因此需要先补什么知识？
        ↓
哪个解释或实际操作改变了理解？
        ↓
现在能做什么，还有什么没做到？
```

主线解释“为什么一路学到这里”，专题按需讲透知识，索引负责找路。不会为了套结构而把一次简单澄清拆成很多文件。

## 核心特点

- **只记录真实经历**：不虚构情绪、进步、日期、分数或“我终于懂了”。
- **保留个人思考**：用有依据的第一视角、原话和熟悉例子唤回记忆。
- **错误紧跟纠正**：原误解标红并明确标注，旁边就能看到准确解释。
- **避免内容散乱**：写清因果过渡和前置依赖；同一份完整解释只保留一处。
- **图形服务理解**：用清楚的箭头、盒子和前后状态区分抽象关系，注明假设与类比边界。
- **如实记录掌握程度**：分清看懂、会辨认、能填空、能独立写和亲手验证。
- **放在合适的位置**：例如为数据结构补 C 语法，应进入课前基础，而非全部塞进正式章节。

“整理笔记”和“修改 skill”有不同授权范围：只请求修改 skill，不代表允许重组已有知识库。

## 安装

下载仓库，或运行：

```sh
git clone https://github.com/Lain006/learning-notes.git
```

将选中的**整个** `learning-notes` 文件夹（含 `references` 和 `agents`）复制到当前 Codex home 下的 `skills` 目录：

- 设置了 `CODEX_HOME`：放到 `$CODEX_HOME/skills/learning-notes`。
- 未设置：放到 `~/.codex/skills/learning-notes`。

例如，中文版使用 `skills/zh-CN/learning-notes`。目标已有同名 skill 时，先比较或备份，再决定替换。安装后在新聊天中使用；保留默认的自动选择能力，也可以显式调用。

## 使用示例

```text
用 $learning-notes 整理这次学习。
保留我的真实疑问、错误、修正和操作过程，
用一条主线串联内容，避免按每个小概念拆出太多文件，
按我知识库现有结构归档。
```

已有笔记零散时：

```text
这些笔记内容准确，但比较散。
用 $learning-notes 为这组笔记梳理一条能顺着读完的主线，
完整解释只保留一处，其余位置用简短过渡与链接连接。
```

继续学习后：

```text
用 $learning-notes 把这次练习接到已有笔记中。
保留之前的错误，更新现在能独立完成什么，
不要把你自动验证过的内容写成我亲手掌握了。
```

提供需要整理的对话、作答、截图或现有笔记。没有个人学习记录时，应说明证据不足，不能编造经历。

## 一个结构示例

可以沿着以下关系组织一段学习过程：

> 函数四种形式 → 接收返回值 → 变量名与值 → 返回与打印 → 运行例子 → 内存位置 → 指针。

关键是解释**为什么需要从上一步走到下一步**。这只是结构示意，不是任何用户的真实经历。具体技术解释可以留在专题，但不点链接也应读懂整段学习过程。

## 格式与验证

适用于 Markdown 知识库，也可适配其他笔记格式；不强制依赖 Obsidian 或特定插件。要求检查实际显示支持、图片长期存放位置、链接及红字可读性；颜色外还要有文字标签。

中英文技能包均通过 skill-creator 自带的结构校验。结构通过不等于教学质量、学习效果或个人掌握程度已获验证。生成笔记时，仍要区分用户亲手实践、整理者自动检查与待验证例子。英文版已检查方法与约束的一致性，尚未经过多场景独立评估。

## 后续改进

欢迎根据真实使用反馈改进证据忠实度、叙事连贯性、归档、篇幅和导航。优先修复具体问题，避免不断叠加必选栏目。修改方法时同步维护两种语言及其参考文档，不自动回写用户已有笔记。

本仓库只包含可复用方法和结构示例，不包含私人聊天、个人笔记、截图、本机路径或凭据。
